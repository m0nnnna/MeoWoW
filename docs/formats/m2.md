# M2

Implementation notes for `crates/m2`. Records what the format actually does and
where it bit us, rather than restating [wowdev.wiki/M2](https://wowdev.wiki/M2).

M2 is the format for every animated object in the game: creatures, characters,
doodads, weapons, spell effects. A stock 3.3.5a install has 22,844 of them.

## Shape

The header is a flat sequence of `(count, offset)` pairs pointing into the rest
of the file. Nothing is self-describing and nothing is bounds-checked, so every
array is validated against the file length at parse time — a bad offset would
otherwise be an out-of-bounds read on data we do not control.

The reader walks header fields **in order** rather than by absolute offset. The
field order *is* the layout, so a missing field shifts everything after it and
fails loudly instead of quietly reading a neighbour.

Version 264 is what 3.3.5a ships, and other versions are rejected: field
positions move between builds, and a wrong layout parses perfectly while
returning nonsense.

## Geometry is not in the `.m2` file

The model holds a vertex pool. The *triangles* live in separate `.skin` files,
one per level of detail — `Foo.m2` is accompanied by `Foo00.skin` (highest
detail) through `Foo03.skin`. `Model::skin_count` says how many exist.

**Indices are two levels deep.** `Skin::triangles` indexes into
`Skin::vertex_map`, and *that* indexes into the model's vertex array. Skipping
the indirection produces geometry that looks plausible and is subtly scrambled,
which is the worst kind of bug to find later.

## Paths in the DBCs are wrong on purpose

`CreatureModelData.model_name` stores `.mdx` paths — a leftover from the
Warcraft III era — while the files shipped since Burning Crusade are `.m2`.
`model_path()` performs the rewrite; a test checks it against all 1,331 rows of
the table rather than a couple of examples.

## Textures are mostly not named by the model

A model's texture slots usually carry `kind != 0`, meaning "the client supplies
this". For creatures, `kind` 11 to 13 are the skins named by
`CreatureDisplayInfo.texture_variation_*`. Only `kind == 0` slots name a file
directly.

So drawing a creature is a three-table walk:

```
CreatureDisplayInfo.id
  -> .model_id            -> CreatureModelData.model_name  (.mdx -> .m2)
  -> .texture_variation_* -> fills the model's runtime texture slots
```

`wow-cli m2 creature <display-id>` runs exactly that.

A batch reaches its texture indirectly as well: `batch.texture_combo_index`
indexes the model's texture combo table, which indexes the texture list. That
double hop is per draw call.

## 16-bit counts overflow, and the fix is a trap

`M2SkinSection.indexCount` and `vertexCount` are `u16`, and a few models exceed
65,535. `World\DUNGEON\Sunwell\Sunwell_Bushes00.skin` has one submesh covering
an index array of 93,456 entries but stores **27,920** — exactly 93,456 minus
65,536. The documented `Level` field carries high bits for the *start* fields,
but it is zero here; the counts simply wrapped.

Submeshes tile the index array in order, so the true span is the distance to the
next submesh's start. **Congruence modulo 65,536 is not sufficient evidence to
use it.** In `Environments\Stars\NexusRaid_SkyA00.skin`, submesh 43 correctly
declares 1,728 indices and sits 67,264 before the next start — and 67,264 is
congruent to 1,728, so a rule that checks only congruence silently corrupts a
valid submesh. That regression was introduced and caught within one survey run.

The repair therefore requires the stored value to be *provably wrong* first —
not a whole number of triangles, or running past the array — and the replacement
to be provably better. `Submesh::counts_repaired` records when it fired.

## Validation

A wrong field offset yields a model that parses cleanly and is nonsense, so
`Model::validate` checks properties the data must have rather than the header:

- **Normals are unit length.** This is the sharpest probe available: they are
  unit vectors by construction, so a wrong vertex stride or intra-vertex offset
  breaks them immediately. Zero normals are tolerated on degenerate vertices.
- **Bone weights sum to 255**, the same idea one field over.
- **Bone parents are in range and acyclic**, since a cycle would hang any
  skeleton walk.

`wow-cli m2 survey` runs all of this across the archive set. Expected result on
a stock install:

```
22779/22844 models parsed, 24626 skins
  9942001 vertices, 15928924 triangles across all levels of detail
  largest model: 35046 vertices, 315 bones
  65 listed paths did not resolve (tombstoned or stale)
no failures
```

## Not parsed yet

Animation tracks are read past but not decoded — bones expose hierarchy and
pivots only. Sequences, lights, cameras, particle and ribbon emitters, and
collision geometry are counted but not interpreted. Animation is milestone 2.3.
